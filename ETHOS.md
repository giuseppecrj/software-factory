# Software Factory Ethos

## Core stance

This project is not trying to build a swarm.

It is trying to build a **lean software factory** with:
- one orchestrator
- many isolated workers
- many isolated reviewers
- artifact-first handoff
- human winner selection

## Product principles

1. **DevEx is a product requirement** — the operator flow must be obvious.
2. **Thin core, fat files** — workflows, skills, templates, and scripts hold most of the opinion.
3. **Verification over vibes** — every candidate needs explicit checks and review artifacts.
4. **Parallelism without chaos** — same-task fanout is good; peer swarms are not.
5. **Rules emerge from failures** — add constraints after repeated mistakes, not before.
6. **Local-first proof first** — prove the loop with worktrees before adding heavier runtime layers.
7. **Readable artifacts beat hidden state** — outputs should be inspectable by humans and agents.
